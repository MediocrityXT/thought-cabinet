# ThoughtCabinet

ThoughtCabinet 的目标，是帮助人建立一个能够持续运转的最小闭环：

`构建认知 -> 产生 Idea -> 进行实践 -> 更新认知`

它关心的不是“收藏了多少资料”，而是如何把零散的信息、想法和经验，逐步整理成一套能够支持判断、决策和行动的认知体系。

## 核心认知模型

本项目建立在以下两个基本判断之上：

1. 人的认知由“事实”和“观点”共同组成。大量观点支撑着我们的想法、决策和行为。
2. 事实天然具有时效性和条件性，因此由事实总结和推导出的观点，同样具有时效性和条件性。

这意味着：在新的场景、新的阶段里，如果我们仍然沿用已经失效的事实或观点，就很容易做出错误判断。

因此，ThoughtCabinet 不是一个单纯的笔记库，而是一个用来维护认知、校正认知、并让认知参与实践的系统。

## 系统如何工作

日常遇到新的材料、新的想法、新学到的事实，或者尚不成熟的个人观点时，用户都可以先把它们投入系统。随后，LLM 会协助完成整理、精炼、分类和提纯，把这些输入转化为结构化的“事实”与“观点”。

用户可以继续通过问答的方式深入挖掘这些内容，并决定哪些内容值得被纳入自己的知识体系。

当用户产生新的 Idea、准备进入项目实践时，系统会尝试基于过去已经沉淀下来的认知，辅助判断它的价值和可行性。实践产生的结果、反馈和现实变化，又会反过来修正旧观点、补充新事实，形成一个不断自我更新的循环。

## 功能模块

### A. 投料口 (The Hopper)

投料口负责接收新的输入。用户可以粘贴 URL、上传文本，或者记录单纯的个人想法、观点，以及最近学到的事实。系统会先帮助用户把这些内容整理成更适合后续处理的形式，再逐步转化为结构化的“事实”与“观点”。

在这个界面里，用户不只是把内容“存进去”，还可以通过问答继续深挖细节，并有选择地将其中有价值的内容纳入自己的知识体系。

投料口的核心功能包括：

1. 维护一个“稍后阅读”的队列和列表。
2. 支持持续向列表中加入新内容，即使暂时来不及处理或审批。
3. 在用户有时间时再进行阅读、整理，并选择性地提取重要的事实和观点。

### B. 认知蓝图 (The Knowledge Blueprint)

认知蓝图是一个接近知识图谱 DAG 的可视化系统，用来展示系统中已经总结出来的事实、观点，以及它们之间的关系。

它不只是简单地把已有内容画出来，还要帮助用户看到认知中的空白、潜在联系，以及值得进一步探索的方向。

认知蓝图需要具备以下能力：

1. 战争迷雾
   - 表示那些尚未被正式纳入认知体系的事实与观点。
   - 在界面上以灰色呈现。
   - 标注出与当前项目或认知高度相关、值得进一步探索的内容。

2. 连线板功能
   - 允许用户像使用“图钉 + 连线”一样手动建立关联。
   - 帮助用户在观点之间发现相似性、依赖关系与潜在共鸣。
   - 挖掘“1 + 1 > 2”的可能性。

### C. 评估委员会 (Assessment Committee)

评估委员会负责评估用户提出的想法，判断它们是否值得继续作为项目推进，以及它们落地的难度和现实价值。

这里的重点不是“给出一个分数”，而是通过不同角度的讨论，帮助用户更快识别一个 Idea 是否值得投入时间、资源和注意力。

评估委员会的核心机制包括：

1. 所有提交的想法都需要经过委员会式评估。
2. 通过多个模型、多个 LLM 共同进行脑暴和分析。
3. 系统根据不同领域调用不同的认知与决策框架，辅助价值评估。
   - 创业项目可使用 Ten Gates 等框架。
   - 学术研究可考虑 novelty、clarity、reproducibility、impact。
   - 日常想法可采用 SWOT 等方式。

评估完成后，系统会将项目映射到“价值四象限”中：

- X 轴代表难度 / 可行性
- Y 轴代表价值 / 影响力

这样，用户可以一眼看出当前所有想法中，哪些是“高可行性且高影响力”的项目，并优先推进它们。

### D. 战术指挥室 (The War Room)

战术指挥室负责把“值得做的事”真正推进下去。实践最困难的地方，往往不是判断这件事值不值得做，而是不知道怎么拆、怎么开始、怎么持续执行。

这个模块的核心目标，是把庞大、复杂但有价值的任务，拆解为可理解、可执行、可持续反馈的最小行动单元。

其核心能力包括：

1. 国策树式任务拆解
   - 最终目标：把一个最终目标拆解成若干子目标。
   - 短期目标：继续把子目标拆解为短期目标。
   - 短期任务：最终细化为非常短期的具体任务。

2. 任务简报
   - 当用户点击某个未完成子任务时，系统生成一份任务简报。
   - 简报至少包括：
     - 当前最小任务目标
     - 相关文档链接 / IDE 命令 / 阅读入口
     - 上下文摘要
     - 前置材料

3. 执行跟踪与反馈
   - 用户执行后，可以记录：
     - 实际做到了哪一步
     - 卡点在哪里
     - 实际耗时是否超出预估
     - 下一步是否需要拆得更细
   - 所有反馈会挂在对应的 Project / Task 下，形成连续的任务日志。
   - AI 会基于过往反馈调整后续任务拆解和优先级，降低执行困难。

## 一句话概括

ThoughtCabinet 试图做的，是把“认知、判断、行动、反馈”连接起来：  
让信息不只被收藏，观点不只停留在脑中，想法不只停留在讨论里，实践结果也不再悄悄散失，而是最终回流到认知本身。
